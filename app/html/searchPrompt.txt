API Reference
POST /keyPressed/autoindex/:dir/:keys

Purpose: Live search / autocomplete. Returns an array of objects whose name starts with or matches :keys.
:dir — data type (pokemon, trainer, user, category)
:keys — characters typed so far
Returns: Array of filtered objects (only those passing conditions)
Use when: user is typing and you want live suggestions

POST /keyPressed/data/:dir/:name/:field

Purpose: Fetch a specific field from a specific record.
:dir — data type
:name — record ID (e.g. abomasnow, abomasnow_2)
:field — the field to retrieve (e.g. moves, hp, name). Use dot notation for nested fields (e.g. hp.max)
Returns: A single filtered object or value
Use when: you know the exact record ID and want specific fields from it


Request Body
Both endpoints require a JSON body. If no filtering is needed, send an empty conds array.
json{
  "conds": [
    {
      "field": "FieldName",
      "cond": "EQUAL | EQUAL_GREAT | EQUAL_SMALL | GREAT | SMALL | HAS",
      "value": "valueToCompare",
      "expect": true,
      "next": "AND | OR"
    }
  ]
}
Condition logic:

expect: true — the condition must be satisfied
expect: false — the condition must NOT be satisfied
next: "AND" — if the current condition fails, the whole chain fails
next: "OR" — if the current condition fails, skip to the next OR
next: "" — last condition, no chaining
Nested fields use dot notation: "HP.max"
Array fields are searched recursively: "Evolutions.To"

Condition types:

EQUAL — exact match
EQUAL_GREAT / GREAT — greater than or equal
EQUAL_SMALL / SMALL — less than or equal
HAS — field exists and is not empty


How to make requests
Always use POST with the body serialized as JSON:
javascriptconst response = await fetch(`/keyPressed/data/${dir}/${name}/${field}`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ conds: [ /* ... */ ] })
});
const data = await response.json();
For autoindex, trigger on user input:
javascriptinputElement.addEventListener("input", async (e) => {
  const keys = e.target.value;
  const response = await fetch(`/keyPressed/autoindex/${dir}/${keys}`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ conds: [ /* ... */ ] })
  });
  const results = await response.json();
  // render results
});

IDs
Record IDs are strings. If duplicates exist, they are suffixed with _2, _3, etc. (e.g. abomasnow, abomasnow_2). The client always knows the correct ID.

Stylesheet
If the user provides a style.css, import it as the base layer. Build all new styles on top of it without overriding its rules unless explicitly asked. If no stylesheet is provided, write self-contained styles.
Visual design
Implement the layout exactly as described by the user in question 5. Take the description literally and creatively — if they say "a room for each result" build rooms, if they say "a pokedex" build a pokedex shell. Do not default to a plain list unless explicitly requested.

General rules

Always ask all 6 onboarding questions before writing any code
Never hardcode data — always fetch it from the API
Conditions must be built dynamically when filtering depends on user input
If Img or Ico fields are present in the template, ignore them unless explicitly told otherwise
